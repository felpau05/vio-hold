1. BLOCKERS

B1 BLOCKER. timing takes the FIRST "engaged" note. An earlier note refuses a good wiggle, with a wrong reason.
   Engage (apb_main.py 251-268) writes "engaged" when it first sees a hold mode. That is also the first row of a
   run when the FC is already in Loiter at the start. The rehearsal read LOITER and POSHOLD on the ground, disarmed
   (rehearsal README step 6B). EVENT_DAY step 6B moves the switch to each position and does not say where to leave
   it. Step 7 item 1 then starts the program. A pilot's switch check at the flight line does the same.
   Cases (the flight's real switch stays in the log; a first note is added):
   - d_ground (note 1 s after the start), 4 of 4 FAIL: "no raw frame in the 15 s before the switch ... The switch
     came before the recording, or the raw files are from another run." Both reasons are wrong.
   - d_test3 (3 s after the start), 4 of 4 FAIL: "Rock the roll and pitch sticks harder" (17 to 18 deg/s).
   - d_test17 (17 s after the start, in the climb), 3 of 4 FAIL. 10 m PASS only because its window held 6 s of the
     wiggle.
   The crew then keeps the ground values (DECISION_CARD row 42). The wiggle flight is lost.
   Correction: B1_timing_switch_choice.patch. timing uses the first "engaged" note whose 15 s before it have log
   rows with no gap over 1 s, no hold mode in the mode column, and no height under min_height_m. The INFO line
   names each note it did not use, and why. Result: d cases 9 of 12 PASS with the flight's own values (30 m fails
   as its flown window does). It also refuses all 20 late-start cases (finding S1). Documents: EVENT_DAY step 6B
   item 5 must say "end with the switch in Altitude mode", and step 7 must say "no switch test after item 1".
   Evidence: evidence/timing_cases_current_code.txt, evidence/timing_cases_compare.txt (rows d_*).

B2 BLOCKER. Nothing checks that the window holds the wiggle. Turning that is not the wiggle passes with wrong values.
   timing gates are: RMS turn rate 20 deg/s or more, 1000 matches, residual 1.0 deg or less, orientation ratio.
   The 8 s wiggle windows turned only 23 to 24 deg/s. At 60 m and 100 m, 15 s windows of the hold in gusts turned
   24 to 40 deg/s (evidence/window_stats.txt). So the rate gate cannot tell them apart.
   Case a (the switch comes N s after the wiggle ends; the flight's engaged note moved; the doc says 4 s):
   no recording has 20 s of Altitude mode after the wiggle. Stand-in: the frames after the real switch (the FC
   holds position in gusts, as a pilot must do by hand in Altitude mode in wind). a2_* = the same, with the mode
   column set to ALT_HOLD before the moved note (what a pilot holding position in Altitude mode leaves).
   Current code, PASS with wrong values and no FAIL:
     a2_still25_60m  66 ms / +39 ms   (26 ms too long; the 30 ms error drifted a 100 m hold 10 m)
     a2_still20_100m 50 ms / +30 ms   a2_still30_60m 50 ms / +30 ms   a2_still10_100m 46 ms / +16 ms
   (a_still* give the same values.) Case a as written, 20 s: 1 of 4 PASS (100 m, 50/+30), 3 FAIL.
   With no pilot input in Altitude mode, the 60 m and 100 m flights turn 0.3 to 6 deg/s: then the rate gate gives
   FAIL (window_stats.txt). Which one the event gives depends on the pilot in the wind: inference, not measured.
   The rehearsal (D1) already saw hold chunks pass with 12 ms / -29 ms.
   Correction: B2_timing_wiggle_check.patch. The 8 s with the most turning must turn at least 3 times the RMS rate
   of the rest of the window, else FAIL and nothing written. The value 3 is a placeholder. It was set on these
   same 4 flights (flown wiggle windows 4.4 to 8.7; windows with no wiggle 1.0 to 1.5; windows that passed with a
   wrong value 1.0 to 1.8; evidence/contrast.txt). There is no hold-out data. In real gusts the "still" parts
   turn more, so a good wiggle can FAIL. That FAIL is safe: keep the ground values. After B1+B2: a2 cases 1 of 32 PASS (a2_still10_30m 42/+24, inside the flown spread);
   the 3 flown PASS cases still PASS with the same values. Documents: EVENT_DAY item 8b must give a limit:
   "switch within 6 s after the settle; if later, wiggle again before the switch".
   Evidence: evidence/timing_cases_compare.txt (rows a_*, a2_*), evidence/window_stats.txt, evidence/contrast.txt.
   The patches were tested on copies only (evidence/builder_test_on_patched.txt: the new test ALL PASSED on both).

6. TASK 2: THE RUN LOG AND THE RAW RECORDING (apb_main.py line numbers of the current file)
a. Same clock, not the same zero. Log.row writes t = fr.t0 (line 331). Raw.add keeps fr.t_grab (line 383) and
   flush saves it (line 408). capture.py lines 4-5: t_grab is time.monotonic, t0 = t_grab - video_delay_s.
   So t_grab = log t + video_delay_s of the flight. Measured: 70.00 +- 0.03 ms on all 4 flights
   (evidence/clock_check.txt). The FC attitude in the chunks uses the same clock (fc_link to_local).
b. run_live reads the newest frame (line 587), then Engage.step reads the FC mode (line 588). fc.mode comes from
   the last HEARTBEAT (fc_link line 154). The "engaged" note goes on the row of that frame (line 637), or on a row
   with no t when no frame came in 0.5 s (line 593; timing then uses the last frame's t, line 1053). So the note
   is on the first frame read after the program saw the new mode. That frame was grabbed just before the mode was
   read. HEARTBEAT comes about once a second (not measured here), so the note is 0 to about 1 s after the switch.
   In the 4 flights the mode column changes on the same row. At the start of a run in a hold mode, the first row
   gets "engaged" with no switch (lines 256-259).
c. Same moment, to the second. The log name uses stamp() at line 575; Raw takes its stamp in __init__ (line 374),
   called at line 576. stamp() is wall time to 1 s (line 347). They differ by 1 s only when a second boundary falls
   between the two calls. Every chunk of one run uses the same base name (lines 374, 406), so a long run with many
   chunks keeps one stamp. A correct pair never differs by more than 1 s. A restart (mode_run, lines 1136-1155) makes
   a new pair with a new stamp, so one flight can have two pairs. The 2 s rule is wider than needed (S2).
