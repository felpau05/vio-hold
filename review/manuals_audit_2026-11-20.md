# Audit of the project against the organizer documents (2026-11-20)

Scope: the Stage 1 package (8 pages), the five OEM (original equipment manufacturer) documents, and the project in /home/paul/Videos/vio-hold-attempt. Stage 2 has not arrived. No project file was changed. No simulator and no test suite ran.

Page numbers: "PDF p.N" is the page number in a PDF viewer. For the APB manual and the aircraft manual the printed number is one lower than the PDF number (PDF p.15 is printed page 14). research/hardware.md uses the printed numbers. The Stage 1 package and the datasheets have no offset.

Short names:
- Stage 1 = the participant rules (Rev 1.3).
- APB manual = DTK-APB-User-Manual-v1.7.2.pdf. APB = Auto Pilot Board.
- Aircraft manual = MRM2-10AI-User-Manual-v1.0.pdf.
- M2 DS = M2-AI-Datasheet-v1.0.pdf.
- D DS = Justice-D-Datasheet-v1.0.pdf. A DS = Justice-A-Datasheet-v1.0.pdf.

Words used: VIO = Visual-Inertial Odometry. FC = flight controller. CSI = Camera Serial Interface. MIPI = Mobile Industry Processor Interface. eMMC = embedded MultiMediaCard (the board flash). SD = Secure Digital card. OSD = on-screen display. GNSS = Global Navigation Satellite System. GPS = Global Positioning System. UART = Universal Asynchronous Receiver-Transmitter (serial port). RNDIS = Remote Network Driver Interface Specification (network over USB). NTP = Network Time Protocol. IMU = Inertial Measurement Unit. IIO = Industrial I/O (a Linux sensor interface). V4L2 = Video for Linux 2. RTH = Return to Home. VTx = video transmitter. EKF = Extended Kalman Filter. SITL = software in the loop (simulator). DS = datasheet. DTB = device tree binary.

Project file shorthand: ED = EVENT_DAY.txt, EH = EIGHT_HOURS.txt, DC = DECISION_CARD.txt, BC = tools/board_check.sh, DP = tools/deploy.sh, JD = tools/profiles/justice_d.json, ST = settings.py, SJ = settings.json, CAP = capture.py, APB = apb_main.py, FCL = fc_link.py, HW = research/hardware.md.

## Answers to questions a to l

**a. Justice D video.** The D DS (p.1) and Stage 1 (p.5 Q3) give 1280x720, 60 fps, MIPI CSI. The APB manual (PDF p.13) gives CSI 1 = /dev/video2, "fixed 1280x720@60", and CSI 2 = /dev/video3. The pixel format of the digital path is not stated, and the CSI port of the event camera is not stated. capture.py has no device default. tools/profiles/justice_d.json:18-21 agrees with the manual. settings.py:67-72 and settings.json:36-37 default to analog /dev/video0. The manual's only GStreamer example is `videotestsrc ! autovideosink`, a display test (PDF p.17), so it shows no camera format. Our reader reads YUYV, UYVY, NV12, GREY and 3-channel BGR (capture.py:226-266). It cannot read Bayer, MJPG or 10-bit formats. The project's YUY2 example is an assumption.

**b. gpioset commands, serial device, baud.** The commands are in EIGHT_HOURS.txt:23-26 and printed as INFO lines in board_check.sh:98-100. They are not in deploy.sh and not in EVENT_DAY.txt, and no script runs them. The project uses /dev/ttymxc2 for MSP (settings.py:21) and, by default, UDP 127.0.0.1:14540 for MAVLink at 230400 baud (settings.py:17-18). The documents state UART3 = /dev/ttymxc2 (APB manual PDF p.15) and a CAN 2 link. They state no baud rate, no protocol and no mavlink-router.

**c. Wall-clock steps.** The manual says the clock is wrong on first boot with only USB (PDF p.11). These steps use it: file names run_, raw_, rec_ and replay_ (apb_main.py:344-345, 372, 573, 649, 933); the calibration date (calib.py:383, 393); the "newest log" choices in EVENT_DAY.txt:155, 170, 191; `ls -t` in deploy.sh:84, 89; the flying check in deploy.sh:121-123; and board_check.sh:114-116. The flight logic uses monotonic time (fc_link.py:121, 158), so it does not depend on the clock.

**d. Logs, raw size, /sdcard.** The default log_dir is "logs" in the program folder (settings.py:147), /home/root/vio/logs by deploy.sh:29, on the board flash; the manual does not say which partition holds /home/root. A raw frame is 640x360 grey = 230,400 bytes: 13.8 MB/s (829 MB per minute) at 60 Hz, or 6.9 MB/s (415 MB per minute) at the profile's 30 Hz. The project names /sdcard only as a value to type (ED:18, EH:36, DC:92, 109) and in one check (board_check.sh:117-119). With the eMMC alone, the "free disk" check needs 5.3 GB and fails.

**e. Board temperature.** The project reads the file once in board_check.sh:107-113 and fails at 85 °C or higher. It does not record the temperature in the run log (apb_main.py:307) or in check. The manual gives /sys/class/thermal/thermal_zone0/temp in millidegrees, a 95 °C shutdown, a fan target of about 62 °C (PDF p.12) and a board range of 0 to 70 °C (PDF p.4).

**f. Python, pip, NumPy, OpenCV, GStreamer.** The documents state none of Python, pip, NumPy or OpenCV. GStreamer appears only in the display test (APB manual PDF p.17). Stage 1 (p.5 Q1) says to treat the specifications as "platform information, rather than a list of preinstalled packages". tools/wheels and board_check.sh assume Python 3.10 to 3.12, aarch64, glibc 2.28 or newer (README.txt:12 says Yocto Scarthgap, which no document states), and pip or pip run from its wheel (board_check.sh:42). With no pip, the wheel runs pip, or the wheels are unpacked with zipfile (README.txt:33-41). With no Python, board_check.sh:30-33 prints FAIL and stops, and there is no offline fallback.

**g. Switch positions and mode names.** The aircraft manual (PDF p.14, p.19) gives TL1: up = Acro, middle = Position Hold, down = RTH, and no Altitude position. EVENT_DAY.txt:150-177 expects Altitude and Position modes. ArduPilot: Engage counts LOITER or POSHOLD as hold (apb_main.py:214), and names ALT_HOLD. PX4: POSCTL or AUTO with LOITER counts (apb_main.py:218-219), and ALTCTL is named. Betaflight and iNav give "mode N", never a hold (apb_main.py:236), and the link refuses them (fc_link.py:365-370).

**h. OSD.** The D DS (p.1) lists the OSD "Voltage, Name, Timer". No document states whether the CSI picture carries the text or how to switch it off, and the APB manual says CSI 1 has no external controls (PDF p.13). The APB's own OSD chip draws on the analog path (PDF p.15). The project assumes text is possible (justice_d.json:3), builds a mask (ED step 3, apb_main.py:939) and refuses black frames that carry text (capture.py:135-156).

**i. Manufacturer limits.** Arming: battery connected, drone bound, throttle lowest (aircraft manual PDF p.20); a GPS fix as an arming condition: not stated. Compass: a 360 degree calibration before Position Hold (PDF p.19). Vibration: 10-inch propellers "generate substantial vibrations" (PDF p.23). Wind: take-off with gusts under 46.3 km/h (M2 DS p.3); a wind limit for hover: not stated. Battery: 6S4P, 29 min, 16.8 Ah (M2 DS p.2). Maximum height: not stated. Propellers: off during USB-C configuration, never with the battery connected indoors (aircraft manual PDF p.4). Heat: VTx at maximum power for more than 60 s without airflow can destroy parts (PDF p.15); fan about 62 °C, shutdown 95 °C, board range 0 to 70 °C (APB manual PDF p.4, p.12).

**j. Firmware and ground tools.** Firmware: ArduPilot, PX4, iNav, Betaflight (APB manual PDF p.3-4; M2 DS PDF p.3; Stage 1 p.5 Q2). Ground tools: Betaflight Configurator (aircraft manual PDF p.20), the Betaflight CLI (APB manual PDF p.20), the Tac.Ctrl controller and IRONghost menu (aircraft manual PDF p.13, p.15), ATAK and the GCS with Fiber (aircraft manual PDF p.5, p.22), orqa_dt_switcher (APB manual PDF p.16), uuu from NXP (APB manual PDF p.18-19). QGroundControl and Mission Planner: not named in any document.

**k. ICM42605 and DPS310.** The APB manual (PDF p.6) says both connect to the SoC. It gives no device path and no driver. board_check.sh:103-106 assumes IIO and lists any device it finds. The program uses the FC's IMU.

**l. Stage 1 rules.** No direct break of the no-GNSS rule (GPS is off, ST:50-61), of the no-marks rule (ED:10, DC row 3) or of the no-hardware rule in the code. Four procedures sit in a grey zone: a team SD card in the aircraft (Q8, Q9; Table 1 row 1), a checkerboard lens that flies (Q10; row 14), laptop-solved numbers (p.2, Q10; row 15), and FC parameter writes under the Stage 2 "configuration rules" (Q8). The phone-map origin for ArduPilot (ST:37-39) does not break a rule but weakens the GNSS-free bonus (row 16).
